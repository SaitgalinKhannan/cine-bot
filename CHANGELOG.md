# Changelog

## [1.1.0] - 2026-03-16

### Добавлено

#### LLM-агент (Этап 7)
- Интеграция с OpenRouter API для обработки естественного языка
- Поддержка моделей: `openrouter/hunter-alpha`, `qwen/qwen3-next-80b-a3b-instruct:free`, `minimax/minimax-m2.5:free`, `openrouter/healer-alpha`
- LangChain для создания агента с инструментами
- 4 инструмента для агента: `add_event`, `list_events`, `search_file`, `delete_event`
- Обработчик естественного языка в `app/handlers/llm.py`
- Системный промпт на русском языке
- Автоматическое определение намерений пользователя

#### Новые возможности
- Общение с ботом на естественном языке без команд
- Примеры: "Добавь премьеру фильма Горизонт 20 апреля в 19:00"
- Автоматический парсинг дат и типов событий
- Fallback на команды при ошибках

#### Документация
- `LLM_EXAMPLES.md` - примеры использования LLM-агента
- Обновлён `README.md` с информацией о LLM
- Обновлена команда `/help` с примерами естественного языка

#### Конфигурация
- Новые переменные окружения: `OPENROUTER_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`
- Обновлён `.env.example` с настройками OpenRouter
- LLM-агент опционален (работает без API ключа через команды)

#### Зависимости
- `openai==2.28.0` - клиент для OpenRouter API
- `langchain==1.2.12` - фреймворк для LLM-агентов
- `langchain-openai==1.1.11` - интеграция LangChain с OpenAI API
- `aiogram==3.26.0` - обновлена версия Telegram Bot API
- `sqlalchemy==2.0.48` - обновлена ORM
- `asyncpg==0.31.0` - обновлен PostgreSQL драйвер

### Изменено
- Обновлена версия с 1.0.0 до 1.1.0
- Handlers теперь включают `llm.py` (обрабатывается последним)
- Команда `/help` теперь показывает примеры естественного языка

### Технические детали
- LLM handler регистрируется последним для обработки всех текстовых сообщений
- Агент использует упрощенную цепочку с `bind_tools()` для совместимости с LangChain 1.2+
- Максимум 5 итераций агента для предотвращения зацикливания
- Temperature 0.1 для более предсказуемых ответов
- Логирование всех запросов к LLM
- Исправлена HTML-разметка в команде `/help` для корректного отображения

### Исправлено
- Совместимость с LangChain 1.2.12 (удален AgentExecutor, используется прямая цепочка)
- HTML-парсинг в команде `/help` (экранирование угловых скобок)
- Конфигурация Docker Compose (переименованы сервисы db → cinedb, bot → cinebot)
- DATABASE_URL обновлен для новых имен сервисов

## [1.0.0] - 2026-03-16

### Реализовано

#### Инфраструктура
- Настроена структура проекта
- Docker Compose с PostgreSQL 16
- Dockerfile для Python 3.12
- SQLAlchemy 2.x + asyncpg для работы с БД
- Alembic для миграций
- Конфигурация через pydantic-settings
- Логирование через loguru

#### Модели данных
- Модель `Event` для событий (премьеры, встречи, дни рождения)
- Модель `YandexFileCache` для кэша файлов
- Миграция `001_initial` с индексами

#### Telegram бот
- Инициализация aiogram 3.x
- Регистрация команд в меню бота
- FSM для пошаговых диалогов

#### Команды
- `/start` - приветствие
- `/help` - справка по командам
- `/addevent` - добавление события через FSM
- `/events` - просмотр ближайших событий
- `/delevent` - удаление события
- `/find` - поиск файлов на Яндекс.Диске
- `/cancel` - отмена текущего действия

#### Функциональность событий
- Пошаговое добавление через FSM (название, дата, тип, напоминание)
- Валидация формата даты (ДД.ММ.ГГГГ ЧЧ:ММ)
- Проверка даты в будущем
- 4 типа событий: премьера, встреча, день рождения, другое
- Настройка напоминаний за N дней
- Просмотр с группировкой по типам
- Удаление по ID

#### Напоминания
- APScheduler для планирования задач
- Ежедневная проверка событий в 09:00 (Europe/Moscow)
- Автоматическая отправка напоминаний за N дней
- Флаг `is_notified` для предотвращения дублей
- Форматированные уведомления с эмодзи

#### Яндекс.Диск
- Интеграция с yadisk SDK
- Рекурсивный обход папок
- Кэширование файлов в БД
- Определение типа файла (video, photo, document, scenario)
- Ежедневная синхронизация в 03:00
- Fuzzy-поиск по названию файла
- Возврат публичных ссылок

#### Сервисы
- `EventService` - CRUD операции с событиями
- `ReminderService` - отправка напоминаний
- `YandexDiskService` - работа с Яндекс.Диском

#### Документация
- README.md - основная документация
- STATUS.md - статус реализации
- EXAMPLES.md - примеры использования
- TROUBLESHOOTING.md - решение проблем
- SUMMARY.md - итоговый отчёт
- QUICKSTART.md - быстрый старт

#### Утилиты
- `bot.sh` - скрипт управления ботом
- `check_setup.sh` - проверка готовности проекта
- `test_setup.py` - тест импортов модулей
- `Makefile` - команды для управления
- `.dockerignore` - исключения для Docker
- `.gitignore` - исключения для Git

### Технические детали

#### Зависимости
- aiogram 3.13.1
- sqlalchemy 2.0.35
- asyncpg 0.29.0
- alembic 1.13.3
- apscheduler 3.10.4
- yadisk 3.1.0
- pydantic-settings 2.5.2
- python-dotenv 1.0.1
- loguru 0.7.2

#### Архитектура
- Асинхронная архитектура (asyncio)
- FSM для пошаговых диалогов
- Сервисный слой для бизнес-логики
- Разделение на handlers, services, models
- Планировщик задач для автоматизации

#### База данных
- PostgreSQL 16
- Async подключение через asyncpg
- Автоматическое создание таблиц
- Миграции через Alembic
- Индексы для оптимизации запросов

### Статистика
- Python файлов: 19
- Строк кода: ~963 (только app/)
- Handlers: 3
- Services: 3
- Models: 2
- FSM состояний: 6
- Команд бота: 7
- Документации: 6 файлов

### Не реализовано (опционально)
- LLM-агент для парсинга естественного языка (Этап 7)
- Unit-тесты для сервисов
- End-to-end тесты
- CI/CD pipeline

### Известные ограничения
- Синхронизация Яндекс.Диска только по расписанию (нет ручной команды)
- Нет проверки прав доступа (все пользователи группы могут управлять событиями)
- Напоминания отправляются только один раз
- Поиск файлов работает только по кэшу (не в реальном времени)

### Требования
- Docker и Docker Compose
- Telegram Bot Token
- Yandex.Disk OAuth Token
- PostgreSQL 16 (через Docker)
